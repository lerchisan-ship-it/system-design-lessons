## SOAP-сервис «Реестр пациентов ветеринарной клиники»

**Бизнес-контекст:** Необходимо разработать SOAP-сервис для интеграции новой веб-системы ветеринарной клиники с устаревшей учетной системой (legacy). Сервис должен предоставлять возможность регистрации новых пациентов (животных) и выгрузки списка уже зарегистрированных пациентов.

**Цель занятия:** Спроектировать WSDL-контракт и XSD-схему для SOAP-сервиса, а затем проверить их работоспособность через Postman и Microcks.

**Модель данных (Сущность `Patient`):**

| Атрибут | Тип данных | Обязательность | Описание и правила валидации |
| :--- | :--- | :--- | :--- |
| `id` | `String` (UUID) | *Генерируется системой* | Уникальный идентификатор пациента. Не передается при создании. |
| `ownerName` | `String` | **Обязательный** | ФИО владельца. Мин. 3 символа, макс. 100 символов. |
| `petName` | `String` | **Обязательный** | Кличка животного. Мин. 1 символ, макс. 50 символов. |
| `animalType` | `String` (Enum) | **Обязательный** | Вид животного. Допустимые значения: `DOG`, `CAT`, `BIRD`, `REPTILE`. |
| `passportNumber` | `String` | Необязательный | Номер ветпаспорта. Если передан, должен соответствовать формату: **две заглавные латинские буквы, дефис, шесть цифр** (например, `AB-123456`). Валидация по регулярному выражению. |

**Формат сдачи работы:**

1. Создать файл `spec.wsdl` по условиям задачи, содержащий:
1. WSDL-контракт с описанием двух методов (`getPatients`, `registerPatient`).
2. Встроенную XSD-схему, описывающую сущность `Patient` и правила валидации всех полей.

2. Конвертировать `spec.wsdl` в Postman-коллекцию:
   ```
   npx @postman/wsdl-to-postman -s spec.wsdl -o collection.json
   ```
3. Модифицировать `collection.json`, добавив в `info` поле `description`:
   ```
   "info": {
       ...
       "description": "version=1.0 - [Description of my collection]"
   }
   ```
4. Импортировать коллекцию в Postman.
5. Импортировать коллекцию в Microcks (инструкция будет выдана преподавателем).
6. Выполнить запрос из Postman в Microcks.

**Дополнительные условия:**
- Для `animalType` в XSD используйте `simpleType` с ограничением `enumeration`.
- Для `passportNumber` используйте ограничение `pattern` с регулярным выражением.
- При ошибках валидации сервис должен возвращать SOAP Fault с fault-кодом `CLIENT_ERROR` (или `400`).
- При внутренних ошибках сервера — SOAP Fault с fault-кодом `SERVER_ERROR` (или `500`).
- WSDL должен содержать все 5 обязательных компонентов: `types`, `message`, `portType`, `binding`, `service`.

## Шаблоны таблиц для описания операций

**Входные параметры (Input) — `getPatients`**
| Имя параметра | Тип данных | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| `animalType` | `String` | Нет | Фильтр по виду животного. Если не передан или пустой — возвращаются все пациенты. |

**Выходные параметры (Output) — `getPatients`**
| Имя параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| `patients` | Массив `Patient` | Список найденных пациентов. Пустой массив, если ничего не найдено. |

**Входные параметры (Input) — `registerPatient`**
| Имя параметра | Тип данных | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| `patient` | `Patient` | Да | Объект пациента без поля `id` (генерируется сервером). |

**Выходные параметры (Output) — `registerPatient`**
| Имя параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| `registeredPatient` | `Patient` | Созданная сущность, включая сгенерированный системой `id`. |
