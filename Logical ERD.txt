Logical ERD — Martin / Crow's Foot notation
@startuml
left to right direction

entity "Пользователь" as User {
    * user_id : Identifier <<PK>>
    --
    email : String
}

entity "Профиль" as Profile {
    * profile_id : Identifier <<PK>>
    --
    user_id : Identifier <<FK>>
    full_name : String
    driver_license : String
    rating : Integer <<derived>>
}

entity "Автомобиль" as Car {
    * car_id : Identifier <<PK>>
    --
    registration_number : String
    brand : String
    daily_price : Decimal
    pledge : Decimal
    status : Enum
}

entity "Аренда" as Rental {
    * rental_id : Identifier <<PK>>
    --
    profile_id : Identifier <<FK>>
    car_id : Identifier <<FK>>
    started_at : Timestamp
    ended_at : Timestamp
    daily_price : Decimal
    pledge : Decimal
    total_cost : Decimal <<calculated, stored>>
}

entity "ДТП" as Accident {
    * accident_id : Identifier <<PK>>
    --
    rental_id : Identifier <<FK>>
    occurred_at : Timestamp
    description : String
    user_guilty : Boolean
}

User ||--|| Profile : имеет
Profile ||--o{ Rental : участвует в
Car ||--o{ Rental : участвует в
Rental ||--o| Accident : сопровождается

@enduml

Основные бизнес-ограничения
Пользователь не может оформить более одной новой аренды в течение одной календарной даты.
Новая аренда не может быть создана до завершения текущей аренды пользователя.
Одна аренда может длиться несколько суток и хранится одной записью.
Сутки аренды составляют 24 часа с момента выдачи автомобиля.
Если автомобиль не возвращён после окончания текущих 24 часов аренды, аренда автоматически продлевается на следующие сутки.
Стоимость первых начавшихся суток является минимальной невозвратной стоимостью аренды.
Стоимость следующих начавшихся суток рассчитывается по ставке Аренда.daily_price, зафиксированной при создании аренды.
Изменение текущего значения Автомобиль.daily_price не должно изменять стоимость уже созданной аренды.
Изменение текущего значения Автомобиль.pledge не должно изменять размер залога уже созданной аренды.
Одна аренда может иметь не более одного зарегистрированного ДТП.
Регистрация ДТП завершает текущую аренду и переводит автомобиль в статус AFTER_ACCIDENT.
Виновное ДТП влияет на рейтинг пользователя; ДТП не по вине пользователя рейтинг не изменяет.
Рейтинг является вычисляемым показателем и определяется на основании истории виновных ДТП пользователя.
Итоговая стоимость аренды рассчитывается при её завершении и после этого сохраняется как историческое значение.
Платёжные операции находятся за границами рассматриваемой системы. Модель хранит денежные условия аренды, но не факт проведения платежа.
Требует уточнения
Необходимо уточнить бизнес-правило о том, какое значение рейтинга используется при расчёте итоговой стоимости аренды:
рейтинг пользователя на момент начала аренды;
либо рейтинг пользователя на момент завершения аренды.
Если необходимо фиксировать рейтинг на момент начала сделки, в сущность Аренда потребуется добавить отдельный исторический атрибут, например rating_at_start : Integer.
