# Корпоративный портал профилей

## Бизнес-контекст

Внутренний корпоративный портал для управления профилями сотрудников. Сотрудники могут просматривать свои данные. Доступ к сервису строго регламентирован политикой безопасности компании. Для контроля доступа используется стандартный механизм **HTTP Basic Authentication**. Это означает, что клиент обязан передавать учетные данные в закодированном виде (**Base64**) в HTTP-заголовке `Authorization`. Сервер не имеет права пропускать запрос к бизнес-логике или базе данных профилей, пока не декодирует эту строку и не проверит логин и хэш пароля по основной базе сотрудников.

## Методы

- `GET /employees/profile`

## Цель занятия

Спроектировать взаимодействие компонентов системы (**Sequence Diagram**) на основе бизнес-требований к REST API.

## Формат сдачи работы

Один файл `.md`, содержащий:

1. Диаграмму последовательности (в формате **Mermaid.js**) для GET-метода.
2. Таблицу контрактов API (входные и выходные параметры для каждого вызова).
3. Таблицу маппинга (если бизнес-логика требует трансформации данных перед отправкой во внешние системы).

## Дополнительные условия

- Используйте явные блоки активации (**Activation Boxes**), чтобы показать время выполнения операций.
- Предусматривайте не только успешный сценарий (**Happy Path**), но и обработку ошибок. Выбор конкретных HTTP-кодов и логики отката остается на ваше усмотрение.
- Все взаимодействия с базой данных и внешними сервисами должны быть явно отражены на схеме.
- Параметры вызовов и их типы остаются на ваше усмотрение, если явно не прописаны в задаче.
- Результаты вызовов и их типы остаются на ваше усмотрение, если явно не прописаны в задаче.
